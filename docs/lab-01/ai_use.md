# Lab 1 — AI Use

## Tool

Claude (Anthropic), used throughout the Lab 1 workflow via chat.

## How it was used

AI assistance was used extensively across the lab, including:

- **Environment setup & troubleshooting**: diagnosing a failed PostgreSQL installation on Windows (service not registered despite the install folder existing), Git/Git Bash vs Windows Explorer path issues.
- **Git & GitHub workflow**: guidance on the branch model (`main` ← `lab1-staging` ← `feature/*`), step-by-step commands for branching, committing, pushing, opening PRs with the correct base branch, and merging.
- **Application code**: the implementation code for the four features (project foundation, `/api/health` endpoint, category seed/model, `/api/categories` endpoint and category list UI) was generated by Claude and then pasted into the project by the student, rather than written from scratch independently.
- **Tests**: the Vitest/Supertest test files were also produced with AI assistance, following the patterns shown in the provided worked examples (`health.test.ts`).
- **GitHub Project board**: guidance on creating the Kanban board with the required `Status` field values (Backlog · Specified · Started · PR Review · Fixing · Done) and organizing Issues onto it.
- **Documentation**: this file and `docs/lab-01/tests.md` were drafted with AI assistance based on the actual test files and project state.

## What the student did independently

- Ran all commands, installed dependencies, and resolved local environment issues (e.g. re-running the PostgreSQL installer, restarting services) by hand.
- Reviewed and pasted AI-generated code into the correct files, and confirmed tests passed locally before committing.
- Made the actual GitHub actions (creating the repo, branches, PRs, merges, Project board, closing Issues) directly through the GitHub UI/CLI.
- Took the required screenshots (success and failure/offline cases) for Part 4 of the submission.

## Reflection

AI use on this lab was heavy, particularly for code generation and Git/GitHub workflow guidance, given significant Windows-specific setup friction (PostgreSQL, path issues) and limited prior experience with the Git branching workflow required. Understanding of *why* each step was needed was reinforced through the step-by-step, confirm-before-proceeding approach used throughout, but the code itself was largely AI-authored rather than independently written.
